## Summary

Phase 8 establishes the persistence foundation for Corretor v2.0 by wiring two singletons (lib/db.ts with Drizzle + postgres.js, lib/redis.ts with ioredis) and creating the PostgreSQL schema (subscriptions and payment_events tables) with full migration support via drizzle-kit.

All package versions confirmed against npm registry. The critical implementation constraint is ESM ("type": "module" in package.json), which triggers a known open drizzle-kit bug: schema imports with .js extensions cause drizzle-kit generate to fail. The workaround is extensionless imports in all files drizzle-kit reads.

Standard dotenv does NOT load .env.local. The correct loader is @next/env (loadEnvConfig), already available via the next dependency — no separate install needed.

The existing vitest.config.ts sets environment: "jsdom". Integration tests opening TCP connections must override to node per-file using the // @vitest-environment node magic comment.

**Primary recommendation:** Schema at lib/db/schema.ts, singletons at lib/db.ts and lib/redis.ts, migrations output to drizzle/ folder, integration tests at lib/db.test.ts and lib/redis.test.ts with // @vitest-environment node header and [integration] describe prefix.

## Implementation Approach

### Schema File Location

Place the Drizzle schema at lib/db/schema.ts. Keeps it colocated with the singleton (lib/db.ts) and separate from Zod schemas (lib/schemas.ts), following the same named-export + colocated-types pattern established there.

### Schema Definition — lib/db/schema.ts

```typescript
import { pgEnum, pgTable, text, timestamp, jsonb } from "drizzle-orm/pg-core";

// MUST be exported — drizzle-kit skips unexported enums (no CREATE TYPE in migration)
export const subscriptionStatus = pgEnum("subscription_status", [
  "active",
  "cancelled",
  "expired",
  "onhold",
]);

export const subscriptions = pgTable("subscriptions", {
  user_token:             text("user_token").primaryKey(),
  stripe_customer_id:     text("stripe_customer_id"),
  stripe_subscription_id: text("stripe_subscription_id"),
  status:                 subscriptionStatus("status"),
  expires_at:             timestamp("expires_at"),
});

export const paymentEvents = pgTable("payment_events", {
  stripe_event_id: text("stripe_event_id").unique(),
  event_type:      text("event_type"),
  payload:         jsonb("payload"),
  created_at:      timestamp("created_at").defaultNow(),
});
```

[CITED: orm.drizzle.team/docs/column-types/pg]
[VERIFIED: pgEnum must be exported for migration generation — github.com/drizzle-team/drizzle-orm/discussions/1914]

### drizzle.config.ts

Place at project root. Use @next/env to load .env.local — standard dotenv does NOT support .env.local files.

```typescript
import { loadEnvConfig } from "@next/env";
import { defineConfig } from "drizzle-kit";

loadEnvConfig(process.cwd());

export default defineConfig({
  dialect: "postgresql",
  schema: "./lib/db/schema.ts",
  out: "./drizzle",
  dbCredentials: {
    url: process.env.DATABASE_URL!,
  },
});
```

[CITED: github.com/drizzle-team/drizzle-orm/discussions/2781 — @next/env for .env.local]
[CITED: orm.drizzle.team/docs/drizzle-config-file — dialect must be "postgresql"]

## Drizzle ORM Setup

### Import Path for postgres.js Driver

```typescript
import { drizzle } from "drizzle-orm/postgres-js";  // NOT drizzle-orm/node-postgres
import postgres from "postgres";
```

drizzle-orm/postgres-js is for the postgres npm package. drizzle-orm/node-postgres is for the pg package. D-08 locks the postgres package. [CITED: orm.drizzle.team/docs/get-started/postgresql-new]

### Dialect String

Use "postgresql" in drizzle.config.ts — not "postgres". Correct regardless of which npm driver is used. [CITED: orm.drizzle.team/docs/drizzle-config-file]

### Migration Output

drizzle-kit generate creates timestamped .sql files in ./drizzle/. The __drizzle_migrations table in the target DB tracks applied migrations. The drizzle/meta/ subfolder holds journal and schema snapshots — commit both.

## Singleton Patterns

### lib/db.ts — Drizzle + postgres.js Singleton

The globalThis guard prevents Next.js dev hot-reload from opening a new postgres connection on every file change. Without it, each save creates a connection that is never closed, eventually exhausting Postgres max_connections.

```typescript
import "server-only";
import { drizzle } from "drizzle-orm/postgres-js";
import postgres from "postgres";
import * as schema from "./db/schema"; // NO .js extension — drizzle-kit bug #1561

const globalForDb = globalThis as unknown as {
  pgClient: ReturnType<typeof postgres> | undefined;
};

const pgClient =
  globalForDb.pgClient ??
  postgres(process.env.DATABASE_URL!, { max: 10 });

if (process.env.NODE_ENV !== "production") {
  globalForDb.pgClient = pgClient;
}

export const db = drizzle(pgClient, { schema });

// Export raw client for test teardown — integration tests call pgClient.end()
export { pgClient };
```

[CITED: github.com/drizzle-team/drizzle-orm/discussions/688 — globalThis singleton pattern]

**Why export pgClient:** Integration tests need await pgClient.end() in afterAll to close the connection. Without it, Vitest hangs indefinitely after tests complete.

### lib/redis.ts — ioredis Singleton

```typescript
import "server-only";
import { Redis } from "ioredis"; // named export — correct for ESM TypeScript

declare global {
  var redisClient: Redis | undefined;
}

const redisClient =
  global.redisClient ??
  new Redis(process.env.REDIS_URL ?? "redis://localhost:6379");

if (process.env.NODE_ENV !== "production") {
  global.redisClient = redisClient;
}

export { redisClient };
```

[CITED: github.com/redis/ioredis/pull/1695 — named export { Redis } fixes ESM TS constructor error]
[CITED: hayven.dev/blog/how-to-setup-redis-using-singleton-pattern — globalThis pattern]

**Named { Redis } vs default import:** ioredis 5.2.5+ added the named export to fix ESM TypeScript constructor type errors. Always use { Redis } in ESM TypeScript projects.

### import "server-only" Guard

Both singletons include import "server-only" as first line. Causes a build error if a Client Component accidentally imports either file, preventing DATABASE_URL or TCP handles from leaking into the browser bundle. No separate install — ships with Next.js.

## Integration Test Strategy

### Environment Override

The existing vitest.config.ts sets environment: "jsdom". Integration tests that open TCP connections fail under jsdom (net, tls built-ins are absent). Override per-file:

```typescript
// @vitest-environment node   <- must be the very first line
import { describe, it, expect, afterAll } from "vitest";
```

[CITED: vitest.dev/guide/filtering]

### Tagging for D-12 (Exclude from Unit-Only Runs)

Use [integration] prefix in describe() names combined with --testNamePattern exclusion.

**package.json scripts to add:**

```json
{
  "test:unit":        "vitest run --testNamePattern "^(?!\[integration\])"",
  "test:integration": "vitest run --testNamePattern "^\[integration\]""
}
```

The existing npm test (vitest run) runs everything — correct for the phase success-criteria check. npm run test:unit safely excludes integration tests when DB/Redis are unavailable.

[CITED: vitest.dev/config/testnamepattern]

### lib/db.test.ts — Pattern

```typescript
// @vitest-environment node
import { describe, it, expect, afterAll } from "vitest";
import { db, pgClient } from "./db";
import { subscriptions } from "./db/schema";
import { eq } from "drizzle-orm";

const TEST_TOKEN = "test-token-phase8";

describe("[integration] Drizzle singleton", () => {
  afterAll(async () => {
    await db.delete(subscriptions).where(eq(subscriptions.user_token, TEST_TOKEN));
    await pgClient.end(); // required — or Vitest hangs
  });

  it("writes and reads a subscriptions row", async () => {
    await db.insert(subscriptions).values({
      user_token: TEST_TOKEN,
      status: "active",
    });

    const rows = await db
      .select()
      .from(subscriptions)
      .where(eq(subscriptions.user_token, TEST_TOKEN));

    expect(rows).toHaveLength(1);
    expect(rows[0].user_token).toBe(TEST_TOKEN);
    expect(rows[0].status).toBe("active");
  });
});
```

[CITED: answeroverflow.com/m/1267499154779930729 — pgClient.end() for postgres.js teardown]

### lib/redis.test.ts — Pattern

```typescript
// @vitest-environment node
import { describe, it, expect, afterAll } from "vitest";
import { redisClient } from "./redis";

describe("[integration] ioredis singleton", () => {
  afterAll(async () => {
    await redisClient.del("test:phase8");
    redisClient.disconnect();
  });

  it("sets and gets a Redis key", async () => {
    await redisClient.set("test:phase8", "hello");
    const value = await redisClient.get("test:phase8");
    expect(value).toBe("hello");
  });
});
```

## Common Pitfalls

### Pitfall 1: drizzle-kit Cannot Parse .js Extension Imports

**What goes wrong:** npm run db:generate produces no SQL file or exits with a syntax error when any schema import includes an explicit .js extension.

**Why it happens:** drizzle-kit uses its own AST parser that does not handle ESM .js extensions. GitHub issue #1561 — open, unfixed as of drizzle-kit 0.31.10.

**How to avoid:** Use extensionless imports in all files drizzle-kit reads:
```typescript
import * as schema from "./db/schema";    // CORRECT
import * as schema from "./db/schema.js"; // BREAKS drizzle-kit generate
```

**Warning signs:** db:generate exits with no .sql file in drizzle/, or a cryptic parse error on the import line.

[VERIFIED: github.com/drizzle-team/drizzle-orm/issues/1561]

### Pitfall 2: pgEnum Not Exported = No Migration Generated

**What goes wrong:** subscriptionStatus defined but not exported. db:generate produces CREATE TABLE without preceding CREATE TYPE. Migration fails with: ERROR: type "subscription_status" does not exist.

**How to avoid:** Always export pgEnum declarations:
```typescript
export const subscriptionStatus = pgEnum("subscription_status", [...]);
```

[VERIFIED: github.com/drizzle-team/drizzle-orm/discussions/1914]

### Pitfall 3: Standard dotenv Does Not Load .env.local

**What goes wrong:** import "dotenv/config" in drizzle.config.ts reads .env only. DATABASE_URL is undefined. drizzle-kit throws Cannot read properties of undefined.

**How to avoid:** Use @next/env:
```typescript
import { loadEnvConfig } from "@next/env";
loadEnvConfig(process.cwd());
```

[CITED: github.com/drizzle-team/drizzle-orm/discussions/2781]

### Pitfall 4: Vitest Hangs After Integration Tests

**What goes wrong:** npm run test:integration completes all assertions but Vitest never exits.

**Why it happens:** postgres.js and ioredis keep open TCP handles. Vitest waits for all async handles to close.

**How to avoid:**
- await pgClient.end() in afterAll of lib/db.test.ts
- redisClient.disconnect() in afterAll of lib/redis.test.ts

### Pitfall 5: jsdom Environment Breaks TCP Connections

**What goes wrong:** Integration tests fail with TypeError: net.createConnection is not a function because jsdom does not support Node.js net/tls built-ins.

**How to avoid:** Add // @vitest-environment node as the very first line of both integration test files.

### Pitfall 6: DB Singleton Imported in Client Component

**What goes wrong:** A Client Component imports lib/db.ts. Next.js bundles postgres.js into the client. Build fails: Module not found: Can't resolve 'net'.

**How to avoid:** import "server-only" as first import in both lib/db.ts and lib/redis.ts.

### Pitfall 7: Multiple Connections During Dev Hot-Reload

**What goes wrong:** Without the globalThis guard, every next dev file save opens a new postgres connection. After ~50 reloads Postgres rejects connections: FATAL: remaining connection slots are reserved.

**How to avoid:** The globalThis guard stores pgClient on global during development.
